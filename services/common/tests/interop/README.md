# Independent Node.js protocol vectors

`../fixtures/encrypted_v2_node.json` is generated by `jose` and `canonicalize`
through Node.js WebCrypto, independently of the Python shared implementation.
Common Python tests consume this committed fixture without a Node installation
or an npm install in the service CI job.

The vector contains public JWKs, synthetic plaintext, and a signed encrypted
object. It contains no private JWK. Recipient keys intentionally correspond to
the publicly known P-256 test scalars 1 and 2; Python reconstructs them in memory
with `cryptography`. These keys provide **no secrecy** and must never be used
outside tests. Signing/root private keys are generated in memory and discarded.

To regenerate with Node.js 24.12 or later:

```sh
cd services/common/tests/interop
npm ci --ignore-scripts --no-audit --no-fund
npm run generate
```

For an isolated npm install, point `FOLIOVIEW_INTEROP_MODULES` to that install's
absolute `node_modules` directory before running `node_vectors.mjs`. The
generator accepts an optional output filename. Repeated runs deliberately
produce new random CEKs, IVs, ephemeral keys and signatures; review fixture
changes rather than assuming byte-for-byte reproducibility.

The Python suite always verifies and decrypts the committed Node vectors. Set
`FOLIOVIEW_INTEROP_MODULES` when running `test_encrypted_interop.py` to enable
the additional Python-to-Node verification and decryption test. Set
`FOLIOVIEW_NODE_BIN` if Node.js 24 is not the default `node` executable. This
reverse test passes only public test-key material through an anonymous pipe;
it never persists or prints the private JWK.

This is fixture-authoring tooling only, not an application dependency or a
client key-management implementation. No network service or cloud resource is
started by the generator or the Python tests.
